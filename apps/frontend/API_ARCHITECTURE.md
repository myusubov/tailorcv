# TaylorCV Frontend API Architecture

This document explains the multi-layered system used to fetch data and handle mutations in the TaylorCV frontend. It is designed for type safety, automatic cache key management, and seamless integration with Clerk and TanStack Query.

---

## 1. The Core: `backendRequest` (`client.ts`)

**Location:** `@/lib/api/client.ts` (Used primarily on the Server Side / API Routes)

This is the "lowest" level of our HTTP stack. It handles:

- **Authentication:** Automatically retrieves the Clerk JWT token and adds the `Authorization: Bearer <token>` header.
- **URL Building:** Combines the `config.apiUrl` with prefixes (default `/api/v1`) and serializes query parameters.
- **Error Normalization:** Converts fetch errors, network errors, and non-200 responses into a unified `ApiResult<T>` type.
- **Next.js Integration:** Support for `tags` and `revalidate` for Next.js Data Cache.

**Result Types:**

- `ApiOk<T>`: `{ ok: true, data: T, status: number }`
- `ApiErr`: `{ ok: false, error: { message, code, details }, status: number }`

---

## 2. Server-Side Fetching: `defineGet`

**Location:** `@/lib/data/_query.ts` (Used in **Server Components** and **Route Handlers**)

This is the server-side twin of the client client-get. It is used when you need to fetch data directly on the server (e.g., inside an `async` Next.js Page or API Route).

**Key Features:**

- **Automatic Cache Tags:** It uses `makeCacheTags` to generate tags like `onboarding-status` or `onboarding-status:user_123`.
- **Next.js Revalidation:** These tags allow you to use `revalidateTag('onboarding-status')` to instantly refresh data across the entire site.
- **Direct Usage:** Returns a promise that resolves to `ApiResult<T>`, suitable for server-side error handling.

---

## 3. Client-Side Fetching: `defineClientGet` + `defineQuery`

**Location:** `@/lib/http/define-client-get.ts` & `@/lib/http/define-query.ts`

These are used when you need to fetch data inside a **Client Component** (using `'use client'`).

**The Workflow:**

1.  **Fetcher:** `defineClientGet` defines the URL and the Cache Key (used by TanStack Query).
2.  **Hook:** `defineQuery` wraps that fetcher into a standard TanStack Hook (e.g., `useGithubConnectionQuery`).

**Why separate them?**

- Client-side needs **Cache Keys** (arrays) for Query invalidation.
- Server-side needs **Cache Tags** (strings) for Next.js Data Cache revalidation.
- Authentication happens differently: Server-side uses `auth()` from Clerk, Client-side uses a proxy or internal token handling.

---

## 4. Mutations & Server Actions: `defineAction`

**Location:** `@/lib/actions/_action.ts` (Used in **Server Actions**)

This is the standard way to define POST, PATCH, or DELETE operations.

**Key Features:**

- **Automatic Revalidation:** When an action succeeds, it can automatically call `revalidateTag` or `revalidatePath`.
- **Cache Sync:** If `revalidate.fromKey: true` is set, it will invalidate the cache tags generated by `defineGet` (the Server-Side Fetcher), ensuring your UI stays fresh.
- **Usage with Client:** Designed to be passed into the `useActionMutation` hook on the frontend.

---

## 5. UI Integration: `useActionMutation`

**Location:** `@/lib/hooks/use-action-mutation.ts`

A specialized version of `useMutation` for **Server Actions** or **POST/PUT** requests.

**Premium Features:**

- **Automatic Toasts:** Displays `toast.success` and `toast.error` automatically.
- **Form Integration:** Automatically maps backend validation errors to `react-hook-form` fields.

---

## 6. Summary of Patterns

### For Server Components (Pages/Layouts)

Use **`defineGet`** inside `@/lib/data/...`.

```typescript
const result = await getOnboardingStatus({ params: { userId } });
```

### For Server Actions (Mutations)

Use **`defineAction`** inside `@/lib/actions/...`.

```typescript
// In actions file
export const myAction = defineAction({ ... });

// In component
const { mutate } = useActionMutation(myAction);
```

### For API Routes

Use the same **`defineGet`** objects used by Server Components.

### For Client Components

Use **`defineQuery`** inside `@/lib/http/...`.

```typescript
const { data } = useGithubConnectionQuery();
```
